## 三、为什么 IP 查询显示不全

### 1. 当前接口的分页行为是正确的

线上复现：

```text
GET /api/relay-stations/1/users?page=1&page_size=100&registration_ip=222.84.41.112&range=all&sort_by=id&sort_order=asc
→ total=153, pages=2, items=100

GET /api/relay-stations/1/users?page=1&page_size=9&registration_ip=222.84.41.112&range=all&sort_by=id&sort_order=asc
→ total=153, pages=17, items=9
```

所以“只返回 9 个”对应的是当前请求的单页条数，不是筛选总数。页面默认只提供 20/50/100，不应把 `items.length` 当成 `total`。

### 2. 原有注册 IP 风险归因在高并发下不可靠

原实现只把 `auth.register` 审计日志按用户创建时间 `[-3 秒,+15 秒]` 做最近邻匹配。恶意注册并发时，多条日志可能落在同一窗口，导致不同用户被错误绑定到同一条日志，风险 IP 计数偏小或偏斜。

本次改动：

- 优先解析注册审计 `request_body.email`，按规范化邮箱精确关联用户；
- 没有请求体邮箱的旧审计才使用时间近邻回退；
- IP 展示和筛选统一规范化；
- 审计、用量或用户消费读取不完整时，前端提示风险数据不完整，自动禁用安全跳过。

## 四、本次新增风险评估

风险配置按中转站保存，入口位于“用户管理 → 风险配置”。

### 可配置项

- 风险评估总开关；
- 观察窗口：1–60 分钟；
- 并发重叠窗口：5–300 秒；
- 五项权重：
  - 同 IP 注册；
  - 同 IP 不同账号同时调用；
  - 同账号不同 IP 同时调用；
  - 疑似机器注册邮箱；
  - 新账号暂无请求；
- 三项命中阈值：同 IP 注册账号数、同 IP 不同账号并发数、同账号并发 IP 数；
- 自动禁用开关与风险阈值 1–100。

默认计分公式：

```text
数量型信号分数 = min(100, 基础分 + max(观察数量 - 命中阈值, 0) × 递增步长)
```

达到阈值即计基础分；超过阈值后，每增加一个账号或 IP 按步长继续加分。用户刚创建且 `last_used_at` 为空才判定“新账号无请求”；基础分设为 0 可关闭该信号，步长设为 0 则只保留基础分、不再递增。不同信号各自计分后求和，总分封顶 100。

默认数量型参数与分数：

| 场景 | 默认参数 | 分数 |
|---|---|---:|
| 同 IP 注册 2 个账号 | 基础 25，步长 2，阈值 2 | 25 |
| 同 IP 注册 5 个账号 | 超阈值 3 个 × 2 | 31 |
| 同 IP 注册 100 个账号 | 递增后封顶 | 100 |
| 同 IP 不同账号并发 4 个账号 | 基础 35，步长 5，阈值 2 | 45 |
| 同账号并发 4 个 IP | 基础 30，步长 10，阈值 2 | 50 |

自动禁用默认关闭，阈值默认 80；达到阈值的建议需结合审计与调用数据完整性确认。

### 建议阈值

- **80–100：高风险**：适合自动禁用，但仅建议在审计、用户列表、用量读取均完整时开启。
- **50–79：中风险**：建议限速、冻结充值/赠送、要求人工复核，不建议直接自动禁用。
- **25–49：低风险**：保留观察和告警。
- **0–24：正常**。

当前实现每分钟评估一次开启了自动禁用的站点；管理员永远跳过。任何关键数据不完整时整轮跳过自动禁用，避免误杀。

## 五、防护建议

### 立即止损

1. 反向代理/WAF 对注册接口按 IP 限速：建议初始 `5 次/10 分钟`，超过后临时封禁 1 小时；验证码发送接口建议 `3 次/10 分钟`。
2. 同 IP 注册账号数超过 3：暂停注册或强制更强验证；超过 5：临时封禁 IP 并告警。
3. 新账号默认余额/赠送额度设为 0 或极低，至少完成邮箱验证、账号冷却和首个请求观察后再发放。
4. 对用户 API 请求设置新账号冷却：注册后前 10–30 分钟低并发、低 RPM；余额小于 0 时硬阻断上游请求，不只在 UI 展示负数。
5. 对同 IP 不同账号并发与同账号多 IP 并发，先限速/冻结，再人工核验；不要把共享 NAT、公司出口、VPN 误判为唯一证据。

### GatewayOps 侧

- 打开风险评估总开关；
- 初始只告警/人工处置，观察 1–2 个事件周期后再开启自动禁用；
- 自动禁用阈值建议从 80 开始，确认审计和用量数据完整后再启用；
- 风险表按风险分数排序，优先查看“同 IP 不同账号并发”和“同账号多 IP”同时命中的账号；
- 监控 `risk_data_complete=false`、上游审计 API 失败和用量读取失败。

### Sub2API/网关侧

- 注册、验证码、登录、API 请求分别限速，不要只限制登录；
- 校验并固定真实客户端 IP 传递链，反向代理只信任明确的代理网段；
- 记录注册审计的 user/email/IP/request_id，并保证审计分页可读取；
- 对单 IP/设备指纹/邮箱域名/ASN 的突增做告警；
- 负余额、冻结余额和请求扣费必须在服务端原子校验，避免并发请求穿透余额检查。
